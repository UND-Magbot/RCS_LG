## 1. 최종 구성

```
서버 PC (고정 IP)
 ├─ MariaDB 12.3          :3306   ← DB (rcs_lg_db)
 ├─ 백엔드 FastAPI        :8002   ← API + 콘솔 HTML + 로봇태블릿 HTML
 └─ 프론트 Next.js        :3000   ← 관제 화면 (3D 모니터링 / 맵 관리 / 로봇 관리)

    ↑ 접속하는 것들
    ├─ 운영자 노트북 브라우저   → http://서버IP:3000  (관제)
    ├─ 배차 콘솔 (태블릿/PC)    → http://서버IP:8002/api/dispatch/console
    ├─ 로봇 부착 태블릿          → http://서버IP:8002/api/dispatch/robot-tablet/{robot_id}
    └─ 로봇 (AutoXing longjack)  ← 서버가 로봇의 :8090 으로 명령
```

> **참고**: 추후 "포트 통합"(프론트를 백엔드가 서빙 → 8002 하나로)을 적용할 예정입니다.
> 적용 후 달라지는 부분은 **§12 부록 A**에 정리해 두었습니다. **지금은 위 구성으로 설치하세요.**

## STEP 1 — Windows 기본 설정 ★ 가장 중요

노트북을 서버로 쓸 때 **실제로 가장 많이 터지는 부분**입니다. DB 설치보다 이걸 먼저 하세요.

> ⚠️ **이 STEP의 명령은 전부 "관리자 권한 PowerShell"에서 실행해야 합니다.**
> 시작 → `PowerShell` 우클릭 → **관리자 권한으로 실행**
> 일반 권한으로 돌리면 "액세스가 거부되었습니다" 류의 오류가 납니다.

### 1-1. 절전 완전 해제

관리자 PowerShell에서 (한 줄씩 실행):

```powershell
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
powercfg /change monitor-timeout-ac 0
powercfg /change disk-timeout-ac 0
```

#### ⚠️ "그룹 정책은 이 전원 구성표 또는 전원 설정에 대한 설정을 무시합니다" 가 뜨면

**이 메시지가 떴다고 실패한 것은 아닙니다.** 정책이 존재하기만 해도 경고가 나옵니다.
**실제 값을 확인**하세요:

```powershell
powercfg /query SCHEME_CURRENT SUB_SLEEP STANDBYIDLE
```

출력 마지막 두 줄이 `0x00000000` 이면 성공입니다:
```
현재 AC 전원 설정 색인: 0x00000000
현재 DC 전원 설정 색인: 0x00000000
```

`0x00000000` 이 아니면 정말 무시된 것입니다. **§11-8** 로 가세요.

### 1-2. 덮개 닫아도 안 자게 ★

**제어판 → 하드웨어 및 소리 → 전원 옵션 → 덮개를 닫을 때 수행할 작업**
→ 전원 사용 시: **아무 것도 안 함**

명령으로 하려면:
```powershell
powercfg -setacvalueindex SCHEME_CURRENT 4f971e89-eebd-4455-a8de-9e59040e7347 5ca83367-6e45-459f-a27b-476b1d01c936 0
powercfg -setactive SCHEME_CURRENT
```

> 이걸 안 하면 **노트북 덮고 자리 뜨는 순간 서버가 죽습니다.**

### 1-3. USB 선택적 절전 / 네트워크 어댑터 절전 해제

장치 관리자 → 네트워크 어댑터 → 해당 어댑터 → 속성 → **전원 관리**
→ "전원을 절약하기 위해 컴퓨터가 이 장치를 끌 수 있음" **체크 해제**

### 1-4. 고정 IP 설정

§0.1에서 확정한 값으로 설정합니다.

```powershell
# 어댑터 이름 확인
Get-NetAdapter | Select-Object Name, Status, LinkSpeed
```

**GUI 권장**: 설정 → 네트워크 및 인터넷 → 어댑터 옵션 변경 → 해당 어댑터 우클릭 → 속성
→ `인터넷 프로토콜 버전 4(TCP/IPv4)` → **다음 IP 주소 사용**

> **유선랜을 권장합니다.** WiFi는 절전·재연결로 끊기기 쉽습니다.

### 1-5. 원격 데스크톱 켜기 (권장)

현장에 안 가고 고칠 수 있게 해둡니다.

설정 → 시스템 → **원격 데스크톱** → 켬

### 1-6. Windows 업데이트 자동 재시작 시간 지정

설정 → Windows Update → 고급 옵션 → **사용 시간** 을 넓게 잡아 테스트 중 재부팅을 막습니다.

### [확인]
```powershell
powercfg /query SCHEME_CURRENT SUB_SLEEP | Select-String "전원 설정 인덱스" | Select-Object -First 3
ipconfig | Select-String "IPv4"
ping -n 2 <로봇IP>
```
- IPv4 주소가 §0.1의 고정 IP와 같은지
- 로봇에 ping이 가는지 (**같은 대역인지 확인**)

## STEP 2 — MariaDB 설치

### 2-1. 설치

MariaDB **12.3** MSI 실행. 설치 마법사에서:

- [x] root 비밀번호: **`1234`** (§0.1의 값. 다르게 하면 뒤의 설정 파일도 전부 바꿔야 함)
- [x] **Enable networking**, Port **3306**
- [ ] "Allow remote access for root" — **체크하지 마세요** (보안). 필요하면 §2-3에서 전용 계정 생성
- [x] Install as service, Service Name: `MariaDB`

### 2-2. 설치 확인

```powershell
Get-Service MariaDB
& "C:\Program Files\MariaDB 12.3\bin\mysql.exe" -u root -p1234 -e "SELECT VERSION();"
```

> `mysql` 은 PATH에 없습니다. **항상 전체 경로로 실행**하세요.
> (2026-08-11에 이것 때문에 헤맨 기록이 있습니다)

### 2-3. (선택) 외부에서 DB에 직접 붙어야 할 때만

백엔드가 같은 PC에 있으므로 **보통은 불필요합니다.** 개발 PC에서 DB를 직접 보고 싶을 때만:

```sql
CREATE USER 'rcs'@'192.168.%.%' IDENTIFIED BY '원하는비밀번호';
GRANT ALL PRIVILEGES ON rcs_lg_db.* TO 'rcs'@'192.168.%.%';
FLUSH PRIVILEGES;
```

```powershell
New-NetFirewallRule -DisplayName "MariaDB 3306" -Direction Inbound `
  -Protocol TCP -LocalPort 3306 -Action Allow -Profile Any
```

> `bind-address` 는 손댈 필요 없습니다. MariaDB 기본이 `0.0.0.0` 입니다 (개발 PC에서 실측 확인).

### [확인]
```powershell
Get-NetTCPConnection -LocalPort 3306 -State Listen | Select-Object LocalAddress, LocalPort
```
`0.0.0.0` 이 보이면 정상.

## STEP 3 — DB 이관

### 3-1. 개발 PC에서 덤프 뜨기

**개발 PC에서** 실행:

```powershell
& "C:\Program Files\MariaDB 12.3\bin\mysqldump.exe" -u root -p1234 `
  --databases rcs_lg_db --single-transaction --routines --events `
  --result-file=C:\temp\rcs_lg_db.sql
```

> `>` 리다이렉트를 쓰지 말고 **`--result-file`** 을 쓰세요.
> PowerShell의 `>` 는 UTF-8 BOM을 붙여서 import 시 깨질 수 있습니다.

파일을 USB나 공유 폴더로 서버 PC에 옮깁니다. (약 3MB)

### 3-2. 서버 PC에서 복원

```powershell
& "C:\Program Files\MariaDB 12.3\bin\mysql.exe" -u root -p1234 -e "source C:/temp/rcs_lg_db.sql"
```

> 덤프 파일 안에 `DROP DATABASE` + `CREATE DATABASE` + `USE` 가 들어 있어서
> **DB를 미리 만들 필요 없이 import만 하면** 됩니다.
> 경로의 슬래시는 `/` 를 쓰세요 (`source` 명령은 `\` 를 이스케이프로 해석).

### [확인]
```powershell
& "C:\Program Files\MariaDB 12.3\bin\mysql.exe" -u root -p1234 -e `
  "USE rcs_lg_db; SHOW TABLES; SELECT id,name,poi_type,rack_size FROM map_pois WHERE is_active=1;"
```
- 테이블 **21개**가 나와야 합니다
- POI 목록에 `R1 / standby / LG2` 가 보여야 합니다 (랙 위치)
- 한글이 안 깨져야 합니다

## STEP 4 — Python + 백엔드

### 4-1. Python 3.11 설치

설치 시 **"Add python.exe to PATH" 체크**.

```powershell
python --version     # Python 3.11.x
```

### 4-2. 소스 폴더 배치

개발 PC의 `RCS_LG` 폴더를 **`C:\RCS_LG`** 로 복사합니다.

**제외할 폴더** (대상 PC에서 새로 만듦):
```
BackEnd\venv\
frontend\node_modules\
frontend\.next\
_db\
```

**반드시 포함할 것**:
```
BackEnd\static\        ← 약 43MB, git에 없음. 빠뜨리면 맵이 안 뜸
```

### 4-3. 가상환경 + 패키지 설치

```powershell
cd C:\RCS_LG\BackEnd
python -m venv venv
.\venv\Scripts\python.exe -m pip install --upgrade pip
.\venv\Scripts\pip.exe install `
    fastapi "uvicorn[standard]" sqlalchemy pymysql apscheduler `
    passlib "bcrypt==4.0.1" python-jose requests websocket-client
```

> ⚠️ **`requirements.txt` 를 절대 쓰지 마세요.** 세 가지 문제가 있습니다:
> 1. **UTF-16 인코딩**이라 pip가 읽지 못함
> 2. 개발자 PC 전체 `pip freeze` 결과(torch·PyQt5·pyrealsense2 등 **약 3GB**)
> 3. 정작 필요한 `apscheduler` 가 들어 있지 않음
>
> ⚠️ **`bcrypt==4.0.1` 버전 고정 필수.** 4.1 이상은 `passlib 1.7.4` 와 충돌해
> `AttributeError: module 'bcrypt' has no attribute '__about__'` 로 로그인이 깨집니다.

위 목록은 `app/` 전체의 import를 전수조사해 뽑은 **실제 의존성**입니다.
(의존 패키지까지 합쳐 40개 정도가 설치됩니다)

### 4-4. 실행 스크립트 수정

`C:\RCS_LG\BackEnd\run_local.ps1` 을 열어 확인/수정:

```powershell
$env:DB_NAME="rcs_lg_db"
$env:DB_HOST="127.0.0.1"      # 서버 PC 자기 자신 (DB가 같은 PC)
$env:DB_USER="root"
$env:DB_PASSWORD="1234"
& "$PSScriptRoot\venv\Scripts\python.exe" -m uvicorn app.main:app --host 0.0.0.0 --port 8002
```

> **운영에서는 `--reload` 를 빼세요.** 파일 감시 때문에 CPU를 계속 먹고,
> 코드가 잠깐 저장 중인 상태에서 재시작이 걸리면 서버가 죽습니다.
> (개발 PC의 `run_local.ps1` 에는 `--reload` 가 있습니다)

## 11. 문제 해결

### 11-1. `pip install` 이 실패한다
- `requirements.txt` 를 쓰고 있지 않은지 확인 (§4-3 경고 참조)
- 회사 네트워크 프록시 문제면 `--timeout 300` 추가

### 11-2. 로그인이 안 된다 / `bcrypt` 오류
```
AttributeError: module 'bcrypt' has no attribute '__about__'
```
→ bcrypt 버전 문제입니다.
```powershell
.\venv\Scripts\pip.exe install "bcrypt==4.0.1" --force-reinstall
```

### 11-3. 로봇이 `online: false`
1. **같은 대역인지 먼저 확인** — `ping <로봇IP>`
2. 로봇 웹 확인 — `http://<로봇IP>:8090/chassis/status` 가 브라우저에서 열리는지
3. DB의 로봇 IP가 실제와 같은지
   ```sql
   SELECT id, name, ip_address, is_active FROM robots;
   ```
4. 로봇 IP가 바뀌었으면 관제 → 로봇 관리에서 수정

> 2026-08-11 사례: DB에 `.110` 으로 등록돼 있었지만 실제 로봇은 `192.168.30.100` 이었습니다.
> 대역 스캔으로 실제 IP를 찾아 DB를 고쳐서 해결했습니다.

### 11-4. 다른 PC에서 접속이 안 된다
1. 방화벽 (§6)
2. 서버 PC의 네트워크 프로필이 "공용"이면 차단이 셉니다 — "개인"으로
3. 백엔드가 `--host 0.0.0.0` 으로 떠 있는지 (`127.0.0.1` 이면 외부 접속 불가)
   ```powershell
   Get-NetTCPConnection -LocalPort 8002 -State Listen
   ```
   `0.0.0.0` 이어야 정상

### 11-5. 관제 화면은 뜨는데 데이터가 안 나온다
`.env.local` 의 `NEXT_PUBLIC_API_URL` 이 잘못됐거나, **IP를 바꾸고 재빌드를 안 한 것**입니다.
```powershell
cd C:\RCS_LG\frontend
npm run build
npm run start
```

> **주의**: 일부 화면(`JobStatusPanel`, `RemoteControlModal`, `통계`)은
> 환경변수가 없으면 `http://localhost:8002` 로 폴백합니다.
> 그래서 **서버 PC에서는 되는데 다른 PC에서는 그 화면만 안 나오는** 현상이 생길 수 있습니다.
> 이건 알려진 문제이고 §12 부록 A 적용 시 해결됩니다.

### 11-6. 맵이 안 보인다
`BackEnd\static\maps\` 폴더가 비어 있는지 확인하세요. git에 없어서 수동 복사가 필요합니다.

### 11-8. 그룹 정책 때문에 절전을 못 끈다

먼저 **정말 안 먹었는지** 확인 (§STEP 1-1 참조). `0x00000000` 이면 문제 없습니다.

정말 무시되고 있다면, 원인부터 파악합니다:

```powershell
# 도메인 소속인가?
Get-CimInstance Win32_ComputerSystem | Select-Object PartOfDomain, Domain, Manufacturer, Model

# 전원 관련 정책 키가 실제로 있는가?
Get-ChildItem -Recurse 'HKLM:\SOFTWARE\Policies\Microsoft\Power' -ErrorAction SilentlyContinue

# 정책 출처
gpresult /r /scope:computer
```

**(a) 로컬 정책이면** — `gpedit.msc` (Windows Pro 이상)
```
컴퓨터 구성 → 관리 템플릿 → 시스템 → 전원 관리 → 절전 설정
→ 관련 항목을 "구성되지 않음" 으로
```

**(b) 레지스트리로 심어진 것이면** — 반드시 백업 먼저
```powershell
reg export "HKLM\SOFTWARE\Policies\Microsoft\Power" "$env:USERPROFILE\Desktop\power_policy_backup.reg"
Remove-Item -Recurse -Force 'HKLM:\SOFTWARE\Policies\Microsoft\Power'
gpupdate /force
```
> 회사 관리 PC면 정책이 자동으로 다시 내려옵니다. 그때는 (c).

**(c) ★ 정책을 못 풀 때의 우회 — 이게 가장 확실합니다**

정책은 "몇 분 뒤 잠들지"를 정합니다. 그런데 Windows에는 **"지금 사용 중이니 잠들지 마"** 라고
선언하는 별도 장치가 있고, **이건 정책보다 우선합니다.**

`C:\RCS_LG\절전방지.ps1` 로 저장:

```powershell
# 시스템이 유휴로 판정돼 잠드는 것을 막는다 (그룹 정책과 무관하게 동작).
# ES_CONTINUOUS(0x80000000) | ES_SYSTEM_REQUIRED(0x1) | ES_DISPLAY_REQUIRED(0x2)
Add-Type -Name Power -Namespace Win32 -MemberDefinition @'
[DllImport("kernel32.dll", SetLastError = true)]
public static extern uint SetThreadExecutionState(uint esFlags);
'@
[Win32.Power]::SetThreadExecutionState(0x80000003) | Out-Null
Write-Host "절전 방지 활성화됨. 이 창을 닫으면 해제됩니다."
while ($true) { Start-Sleep -Seconds 60 }
```

확인:
```powershell
powercfg /requests
```
`SYSTEM:` 항목에 `[PROCESS] ...powershell.exe` 가 보이면 걸린 것입니다.

STEP 7의 `서버시작.bat` 에 아래 줄을 추가해 자동 실행되게 하세요:
```bat
start "KeepAwake" powershell -WindowStyle Minimized -ExecutionPolicy Bypass -File "C:\RCS_LG\절전방지.ps1"
```

> 이 방법은 **"자동으로 잠드는 것"만** 막습니다. **덮개를 닫았을 때의 동작은 별개**이므로
> §STEP 1-2 를 반드시 따로 설정하세요.

**(d) 최종 판정은 실측으로**
```
백엔드 실행 → 덮개 닫기 → 5분 대기 → 다른 PC에서 http://서버IP:8002/ping
```
응답이 오면 무슨 경고가 떴든 상관없습니다.

### 11-7. 재부팅 후 자동 시작이 안 된다

### 참고: DB 복제 절차 (VESA 때 실제로 쓴 스크립트)

`rcs_basic_db → rcs_vesa_db` 로 옮길 때 쓴 방법입니다. **`CREATE TABLE LIKE` 는 FK 를 복사하지 않아**
FK 를 따로 복원해야 한다는 점이 핵심입니다. (LG 는 `mysqldump` 방식을 권장 — STEP 3)

```python
# 1) DB 복제 (스키마 + 데이터)
import pymysql
conn = pymysql.connect(host='192.168.0.21', user='root', password='1234', charset='utf8mb4')
cur = conn.cursor()
cur.execute("CREATE DATABASE 새DB CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci")
cur.execute("USE 원본DB"); cur.execute("SHOW TABLES")
tables = [r[0] for r in cur.fetchall()]
cur.execute("SET FOREIGN_KEY_CHECKS=0")
for t in tables:
    cur.execute(f"CREATE TABLE 새DB.`{t}` LIKE 원본DB.`{t}`")
    cur.execute(f"INSERT INTO 새DB.`{t}` SELECT * FROM 원본DB.`{t}`")
cur.execute("SET FOREIGN_KEY_CHECKS=1")
conn.commit()

# 2) FK 정의 복원 (CREATE TABLE LIKE 는 FK 미복사 — ALTER 로 별도 추가)
#    information_schema.KEY_COLUMN_USAGE + REFERENTIAL_CONSTRAINTS 조인으로
#    원본 DB 의 FK 를 추출해서 새 DB 에 동일하게 ADD CONSTRAINT
```
