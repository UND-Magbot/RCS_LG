## 1. 한 줄 요약

> **"랙 보관 위치(R)에서 호출하면, 짝 작업지점(J)까지 랙을 가져다 놓고 충전소로 돌아온다."**
> 1 호출 = 1 편도. 로봇 부착 태블릿 확인 없음. 큐가 비면 충전소 복귀.

## 2. 현장 배치 — 이걸 먼저 알아야 나머지가 읽힌다

**2026-08-24 LG 이승현 책임 통화(15:50)로 확정.** PPT 도형 좌표로 교차검증됨(§9).

| 구역 | 포함 POI | 그 구역 작업자가 하는 일 |
|---|---|---|
| **구역 A** | **R1 + J2** | R1 에서 **호출**(랙을 J1 로 보냄) · J2 에서 **확인**(받은 랙 치움) |
| **구역 B** | **J1 + R2** | R2 에서 **호출**(랙을 J2 로 보냄) · J1 에서 **확인** |

**두 구역은 100m 이상 떨어져 있다.** 랙 흐름은 `R1(A) → J1(B)` 과 `R2(B) → J2(A)` 로 **순환**한다.

```
        <-----------  100m 이상  ----------->
+----------------------+      +----------------------+
|       구역 A          |      |       구역 B          |
|  R1 (호출)  ------------------>  J1 (확인)          |
|  J2 (확인)  <------------------  R2 (호출)          |
+----------------------+      +----------------------+
```

### ★ 호출 버튼은 R, 확인 버튼은 J

> LG 요구(통화 13:44): "R1하고 R2의 **호출 버튼**을 넣어 주시면 되고, J1과 J2의 **확인 버튼** 그걸 넣어 주시면 돼요."

이유(통화 12:03): **"J1에 있는 사람은 100m 떨어진 R1의 대차가 있는지 없는지를 어떻게 호출을 해요?"**
→ **랙이 눈앞에 있는 사람만 호출할 수 있다.** 초기 구현은 J 에서 호출하게 돼 있었고, 이 지적으로 옮겼다.

반대 방향 문제도 같이 해결한다 — R 옆 작업자는 100m 밖 J 가 비었는지 모른다.
그래서 **R 화면이 짝 J 의 랙 점유 상태를 보여주고, 랙이 남아 있으면 호출 버튼을 아예 그리지 않는다.**

태블릿은 **4대** (R1·R2·J1·J2 각 1대). PPT 준비물 `Tablet: 4개` 와 일치.

## 3. 확정 사양

| # | 항목 | 확정 내용 |
|---|---|---|
| 1 | **J↔R 매핑** | **J1-R1 / J2-R2 고정** (`job_points` 테이블) |
| 2 | **호출 위치** | **R1 · R2** (랙 보관 위치). J 에는 호출 버튼 없음 |
| 3 | **확인 위치** | **J1 · J2** — [확인 — 랙을 치웠습니다] |
| 4 | 하차 후 | **로봇 부착 태블릿 확인 없음** — 자동 진행 |
| 5 | 큐 | **FIFO**. 비면 충전소 복귀 |
| 6 | 복귀 중 호출 | **수락** — 충전소를 포기하고 이어받음 (제약은 §8-1) |
| 7 | R 에 랙 없음 | align 재시도 소진 → 랙 없음 간주 → 로그 남기고 **다음 큐 진행 / 없으면 충전소** |
| 8 | **J 에 랙 있음** | **짝 R 의 호출 버튼 비활성** + "J 에서 치우고 [확인]" 안내. J 의 [확인]이 유일한 해제 수단 |
| 9 | 복귀 | **랙 반납 단계 없음** (랙은 J 에 두고 옴 → 빈 몸으로 충전소) |
| 10 | 규모 | 로봇 **1대**, 작업지점 **J1·J2** 2개 (PoC) |

### PoC 에서 제외한 것 (2026-08-24 사용자 결정)

| 항목 | 사유 |
|---|---|
| 역방향 J→R (PPT 운영시나리오 #1-2 / #2-2, 빈 대차 회수) | LG 가 "1-1번만 보면 된다" 로 안내. 차후 검토 |
| 도착 알람 (경광등·음성) | PPT 요구사항이나 HW 제어 필요. 차후 |
| **랙 있음 → R 반납 후 복귀 시퀀스** | ① UI 가 호출을 막아 정상 경로에선 발생 안 함 ② **라이다 판정이 불가**(§8-5)해 트리거 자체가 불가능 |
| 라이다 기반 랙 유무 자동 판정 | **실측 결과 불가** — §8-5 |

### 운영 규약 (코드로 막지 않는 것)

- **J 에 놓인 랙은 작업자가 치운다** — 로봇의 회수 공정은 없다
- 치운 뒤 **반드시 J 태블릿에서 [확인]** — 누르지 않으면 짝 R 의 호출 버튼이 살아나지 않는다

## 4. 시퀀스

```
[충전소 C1]
   |  R 호출  (R poi id -> 서버가 매핑된 J 로 치환)
   v
J<->R 매핑 조회        (J1->R1 / J2->R2)
   v
R 이동 · align_with_rack · jack_up
   |
   +- 재시도 소진 -> 랙 없음 -> 활동로그 기록 --+
   v                                          |
J 이동 · jack_down · 전진 이탈 0.7m             |
   v                                          |
J 점유 표시 (occupied=true)                     |
   |   -> R 타일 호출 버튼 잠김 / J 타일 [확인] 노출 |
   v                                          |
대기 예약 있나?  <-------------------------------+
   +- 있음 -> 그 J 의 R 로  (충전소 생략)
   +- 없음 -> returning -> ★복귀 직전 재확인 -> [충전소 도킹]
```

**충전소 도킹은 2단계** — 사전 접근 POI(`C1-1`) 경유 후 `charge` 이동.

**점유 해제 흐름**

```
작업자가 J 의 랙을 치움
   v
J 태블릿/콘솔 [확인 — 랙을 치웠습니다]
   v   POST /poi/{J}/rack-cleared      (R id 로 불러도 짝 J 를 해제한다)
occupied = false
   v   폴링 2초
R 타일 호출 버튼 자동 활성화
```

## 5. 구현 내용

### 5-1. 신규 테이블 `job_points`

```
area_id · j_poi_name · r_poi_name · occupied · occupied_at
```

**POI id 가 아니라 이름으로 저장한다.** 맵을 다시 동기화하면 POI 가 삭제·재생성돼 id 가
바뀌기 때문. (`charging_id`/`standby_id` 를 이름으로 백업·복원하는 `crud/map.py` 와 같은 이유)

기존 테이블은 **하나도 변경하지 않았다.** `Base.metadata.create_all` 이 없는 테이블만
자동 생성하므로 **수동 CREATE/ALTER 가 필요 없다.** 되돌릴 때도 이 테이블만 지우면 된다.

> 검토했던 대안 — `map_pois` 에 `linked_poi_id` 컬럼 추가(A안)는 ① 수동 ALTER TABLE 필요
> ② 맵 재동기화 시 매핑 소실 때문에 기각. 이름 규칙 자동 매칭(C안)은 POI 이름 변경에 취약해 기각.

### 5-2. 모드 분기 — 기존 동작 무영향

```python
mapping = job_mapping_for_poi(first_poi_id) if with_rack else None
if mapping:   # 배송 모드  (_worker_loop_delivery)
else:         # 기존 인터랙티브 모드 (_worker_loop, 콘솔 경유지 등록)
```

**매핑이 등록된 POI 만 새 시나리오로 돈다.** J1·J2 에만 매핑을 넣었으므로 다른 POI 는
종전과 완전히 동일하게 동작한다. **롤백 = 매핑 삭제** (코드를 되돌릴 필요 없음).

```
DELETE /api/dispatch/job-points/J1?area_id=26
```

UI 도 같은 기준으로 갈린다 — 콘솔의 `legacyTileHtml()` / 태블릿의 기존 `render*()` 가
매핑 없는 POI 에 그대로 쓰인다. **롤백 경로를 보존하려고 지우지 않고 남겼다.**

### 5-3. 호출을 R 로 옮긴 방식 — 배차 코드는 안 건드림

R 타일의 호출 버튼은 **R 의 poi_id** 로 기존 호출 API 를 그대로 부른다.
서버가 입구에서 **매핑된 J 로 바꿔 끼운다**:

```python
# routers/dispatch.py  poi_call()
if poi.poi_type == "standby":
    jp = get_job_point_by_r(db, area_id, poi.name)   # R 이름 -> 매핑
    poi_id = <같은 맵의 jp.j_poi_name POI id>          # 이후 로직은 전부 J 기준
```

덕분에 `call_to_poi` · 배송 워커 · 예약 큐는 **한 줄도 바뀌지 않았다.**

### 5-5. API

| 메서드 | 경로 | 용도 |
|---|---|---|
| GET | `/api/dispatch/job-points?area_id=` | 매핑 목록 + 점유 상태 |
| POST | `/api/dispatch/job-points` | 매핑 등록/수정 |
| DELETE | `/api/dispatch/job-points/{j_poi_name}?area_id=` | 매핑 삭제 |
| POST | `/api/dispatch/poi/{poi_id}/rack-cleared` | 작업자 [확인] — 점유 해제. **J id 정상 · R id 도 허용**(짝 J 를 푼다) |
| POST | `/api/dispatch/poi/{poi_id}/call` | 호출. **R id 면 매핑된 J 로 치환.** 점유 시 409 |

호출 API 는 점유 시 **409 + 한국어 메시지**를 반환한다. 새 UI 는 애초에 버튼을 안 그리므로
정상 경로에선 뜨지 않고, **2차 안전망**으로만 남는다(다중 화면·폴링 시차 대비).

### 5-6. 예약 경로의 랙 점유 가드 — 이름이 헷갈리는 두 값

| 함수 / 필드 | 뜻 | 출처 |
|---|---|---|
| `occupied_poi_ids()` | 다른 로봇이 그 자리를 목표로 잡고 있다 | `dispatch_sessions` |
| `job_points.occupied` | 그 자리에 **랙이 놓여 있다** | `job_points` |

예약이 자동 소화되는 두 경로(`try_fulfill_reservations`, `_take_next_reservation_if_continuable`)는
**앞엣것만 보고 있었다.** `rack_occupied_at_poi()` 로 랙 점유도 확인하게 했다.

> 랙 점유 시 **예약은 `waiting` 으로 유지한다.** 소진(fulfilled) 처리하면 호출이 통째로 사라진다.

### 5-7. 숨긴 기능 (배송 모드 한정)

| 기능 | 사유 |
|---|---|
| [경유지 등록] · [다음 위치 지정] | 배송은 R→J 1회. 경유지 개념 없음 |
| 서빙 호출 | 로봇이 lifting 1대뿐 |
| 리프팅 — 렉 없이 | 배송은 항상 랙을 싣고 감 |

호출 선택지가 하나만 남아 **호출 모달을 띄우지 않고 바로 호출**한다.
**삭제가 아니라 숨김** — 매핑 없는 POI 에서는 종전 UI 가 그대로 뜬다(롤백 경로 보존).

### 5-9. 화면 응답성 · 경합 (2026-08-24 저녁 실측으로 발견)

버튼이 **눌렀다 되돌아가고, 화면이 20초씩 멈췄다 튀는** 증상이 있었다. 원인 셋:

**① 오프라인 로봇 프로브가 화면 폴링을 붙잡음**
`console/status` 안에서 로봇 온라인 여부를 **실제로 찔러본다.** 캐시 TTL 15초라 15초마다
재조회하는데, 오프라인 로봇(.100)은 응답이 아니라 **타임아웃을 기다려야 해서 20초 넘게** 걸린다.
그동안 콘솔이 통째로 멈췄다가 한꺼번에 갱신된다.

- 화면 폴링은 `online_ips_cached(..., block=False)` — **기다리지 않고** 캐시 값으로 즉시 답하고
  갱신은 백그라운드 스레드에 맡긴다. **실제 배차는 `block=True`(정확)** 로 그대로 둔다.
- 오프라인 판정은 `LIVE_CACHE_TTL_OFFLINE = 60초` 로 늘렸다(온라인은 15초 유지).

| 40회 연속 측정 | 이전 | 이후 |
|---|---|---|
| 중앙값 | — | **0.011s** |
| 최대 | **20s+ 타임아웃** | **0.033s** |
| 1초 초과 | 15초마다 | **0회** |

**② 대기 예약을 가용 로봇에서 안 뺐음**
로봇이 유휴가 된 순간부터 예약이 실제 배차될 때까지의 공백에 **"가용 1대"** 로 계산돼,
다른 R 타일에 [로봇 호출] 이 떴다. → `_available_robot_counts` 가 **대기 예약 수만큼 차감**한다.

**③ 낡은 폴링 응답이 낙관적 화면을 덮어씀**
`refresh()` 가 `pendingActions` 를 **요청 보내기 전에만** 검사했다. 이미 날아간 요청은 못 막아,
조작 직전에 떠난 응답이 뒤늦게 도착해 화면을 되돌렸다.
→ `refreshSeq` 일련번호로 **응답을 받은 뒤에도** 검사한다(더 최신 요청이 있으면 버림 + 조작 중이면 안 덮음).
추가로 내용이 같으면 그리드 DOM 을 다시 만들지 않는다.

### 5-8. 랙 없음 판정

`align_with_retry` 가 4단계(그대로 → 재로컬화 → 후진 0.5m → 측면 우회)를 모두 쓰고도
실패하면 **랙 없음으로 간주**한다. 코드가 "랙이 없어서"와 "정렬이 틀어져서"를 구분할 수는
없으므로, 재시도를 다 쓴 것을 기준으로 삼는다. 활동 로그에 `rack_missing` 으로 남긴다.

### 7-4. 구현 중 발견해 고친 버그 2건

1. **`rack-cleared` 가 R id 를 받으면 조용히 아무것도 안 했다.**
   `set_job_point_occupied` 는 `j_poi_name` 으로만 조회 → R 이름은 매칭 실패 →
   `{"ok":true,"message":"매핑되지 않은 위치입니다"}` 로 **성공 응답**. 작업자는 풀린 줄 알지만
   점유는 그대로. 호출 버튼이 R 로 옮겨지며 안전망 모달이 R id 로 이 API 를 부르게 돼
   실제로 닿는 경로가 됐다. → R→J 치환 추가.

2. **`rack_occupied_at_poi()` 의 예외 처리 범위가 의도와 달랐다.**
   `job_mapping_for_poi()` 를 `try` **밖**에서 호출 → 이 함수도 DB 를 치므로 DB 장애 시 예외가
   배송 워커로 전파되어 **랙을 든 채 세션 failed**. `try` 안으로 옮김.

### 7-5. 감시 중 발견해 고친 버그 2건 (배송 워커)

**① 중지 신호를 "랙 없음" 으로 뭉갬 — 안전 문제**
`_pickup_at_poi` 가 `align_with_retry` 의 예외를 `except Exception` 으로 잡아 `False` 를 돌려줬다.
`jack_service` 에서 `RuntimeError` 를 쓰는 곳은 **중지 신호 두 곳뿐**인데(`_check_stop`,
`zone 대기 중 중지`) 그것까지 삼켰다. 결과:
- 활동 로그에 **거짓 `rack_missing`** 이 남는다
- `_check_stop` 이 플래그를 `pop` 하므로 **중지가 소비된다** → 대기 예약이 있었다면
  **강제 종료를 눌렀는데 로봇이 다음 작업을 시작**한다
→ `except RuntimeError: raise` 로 그대로 올려보낸다(세션 `failed` + 예약 롤백).
기존 인터랙티브 `_pickup_at_standby` 는 예외를 안 잡아 원래 정상이었다 — **배송 워커 신설 시 들어간 회귀**.

**② 랙 없음으로 끝나면 세션이 안 닫히고 복귀도 안 함**
```python
if nxt is None:
    break        # 주석은 "충전소 복귀" 였지만 실제로는 아무 일도 안 일어남
```
세션이 `picking_up` 인 채 남고, 그 세션의 `target(R)` 때문에 **로봇이 충전소에 있는데도
R 타일이 계속 "작업 중"** 으로 보였다(유령 세션 106, 실측).
→ `returning` → `_park_at_charger()` → `completed` 로 실제 복귀시킨다.
