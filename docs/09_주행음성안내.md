## 2. ★ 오디오는 8090이 아니라 9000 채널에 있다

우리가 평소 쓰는 **8090(섀시 REST)에는 오디오 API가 없다.** 공식 문서 22개 페이지를
전수 확인했고, 후보 엔드포인트 7개를 직접 찔러도 전부 404였다.

오디오는 **`ws://<robot_ip>:9000/`** 명령 채널에 있다. AutoXing JS-SDK가 LAN 모드에서
쓰는 채널이고, `@autoxing/robot-js-sdk` 번들을 분석해 프레임 규격을 알아냈다.

| 포트 | 정체 | 용도 |
|---|---|---|
| 8090 | 섀시 REST | 기존 배차·이동·잭업·맵 (오디오 없음) |
| **9000** | **명령 WS + 상태 스트림** | **음성 재생·볼륨, 1초마다 상태 수신** |
| **9001** | **FastAPI** | **내장 음원 다운로드, 설정 조회. `/docs` 열려 있음** |
| 9002·9003 | server / queueTask | 미사용 |

자세한 채널 배경은 `.claude/agents/rcs-lg-robot.md` 와 메모리 참조.

## 3. 통신 구조

```
   서버 (백엔드 8002)                              로봇 192.168.30.110
   ┌────────────────────┐                        ┌────────────────────┐
   │ robot_voice        │ ① ws://로봇:9000 (상시) │ 명령·상태 :9000    │
   │  감시 스레드        │◀───────────────────────│                    │
   │                    │   상태 1초마다 push      │                    │
   │                    │                        │                    │
   │                    │ ② ws://로봇:9000 (단발) │                    │
   │                    │───────────────────────▶│                    │
   │                    │   재생 명령 (5초마다)    │                    │
   │                    │                        │                    │
   │ /static/audio/lg/  │ ③ http://서버:8002      │ 스피커             │
   │                    │◀───────────────────────│                    │
   │                    │   로봇이 mp3 받아감      │                    │
   └────────────────────┘                        └────────────────────┘
```

| | 방향 | 수명 | 내용 |
|---|---|---|---|
| ① | 서버 → 로봇 접속 | **상시**. 끊기면 5초 뒤 재연결 | 로봇이 1초마다 상태 push |
| ② | 서버 → 로봇 | **단발** (약 1.5초, 응답 받고 끊음) | 재생 명령 + 응답 `code:0` |
| ③ | **로봇 → 서버** | 매 재생마다 | mp3 GET (18KB) |

**②에서 연결을 따로 여는 이유**: ①은 1초마다 상태가 쏟아지는 스트림이라, 명령을 섞으면
어느 응답이 내 명령의 것인지 골라내기 어렵다. 명령마다 깨끗한 연결을 쓰면 `commandId` 로
확실히 짝지을 수 있다.

**③이 유일하게 로봇→서버 방향** — 현장 LTE(CGNAT)에서 검증되지 않은 방향이다. §8 참조.

### 시간 순서
```
t=1.0  로봇→서버  {"speed":0.30}        서버: 움직인다
t=1.0  서버→로봇  startPlayAudio
t=1.1  로봇→서버  GET 01_moving.mp3
t=1.2                                  🔊 "이동중입니다" (1.3초)
t=6.0  서버→로봇  startPlayAudio        (5초 경과 → 2회차)
 …
t=20.0 로봇→서버  {"speed":0.00}        멈췄나?
t=23.0                                 3초 지속 → stopPlayAudio
```

## 4. 명령 규격

```json
{"deviceId":"<SN>", "id":"<uuid>", "cmd":"startPlayAudio",
 "args":{"mode":2,
         "url":"http://192.168.30.2:8002/static/audio/lg/01_moving.mp3",
         "audioId":"", "volume":80,
         "interval":-1, "num":1, "duration":8},
 "timeoutSec":15, "needConfirm":true, "timestamp":<ms>}
```
- 정지: `cmd:"stopPlayAudio", args:{mode:2}`
- 볼륨: `cmd:"setVoice", args:{type:0~100, mode:2}`
- 응답 `code:0` = **명령을 받았다는 뜻이지 소리가 났다는 뜻이 아니다.**

### ★ 반드시 알아야 할 두 가지

**① `mode: 2`(섀시)를 쓴다.**
`mode 1`은 상위기(Host) 담당이다. S300에서 mode 2로 재생이 확인됐고,
**L150처럼 섀시만 있는 기종에도 그대로 넘어갈 가능성이 높다.** mode 1로 만들면 L150에서 깨진다.

**② `interval`·`num` 은 동작하지 않는다 (2026-09-03 실측).**
문서에 있고 `code:0` 도 돌려주지만 실제로 반복 재생되지 않는다.
- `interval:5, num:-1` → 소리 안 남
- `interval:-1, num:1` → 정상 재생

→ **반복은 서버가 주기적으로 다시 쏜다.** 1회 재생만 보내고 `interval_sec` 마다 재전송.

## 5. 주행 판별 — `speed` 하나만 본다

9000 상태의 **`speed`(실제 바퀴 속도)** 로만 판정한다. `MOVING_SPEED = 0.02` 초과면 주행 중.

**`moveState` 는 쓰지 않는다.** 양방향으로 어긋나기 때문이다:
- 원격제어로 밀면 `moveState=idle` 인데 로봇은 움직인다
- 경로만 생성되고 못 움직이거나 원격 모드로 취소되면 `moveState=moving` 인데 로봇은 서 있다
  → 실제로 **서 있는 로봇이 "이동중입니다"를 계속 외치는 사고가 발생**(2026-09-03)

**정지 유예 3초** (`stop_delay_sec`): 감속·잠깐 멈춤마다 소리를 끄면 뚝뚝 끊긴다.
원격제어 실측에서 `speed` 가 1~4초 단위로 0을 찍는 것을 확인해 넣었다.

같은 상태 스트림에 `hasObstruction` · `hasPersonAhead` 도 있어 나중에 확장 가능.

## 7. 구현

### 파일
| 파일 | 내용 |
|---|---|
| `app/services/robot_voice.py` | 9000 WS 래퍼 + 로봇별 감시 스레드 |
| `app/routers/settings.py` | `GET·PATCH /api/settings/voice`, `GET /api/settings/voice/audio-list` |
| `app/routers/robot.py` | `POST /api/robots/voice/test/{ip}`, `/voice/stop/{ip}` |
| `app/main.py` | lifespan 에서 `robot_voice.start()/stop()` |
| `app/templates/dispatch_console.html` | 원격제어 모달 UI |

### 설정 (`BackEnd/static/system_settings.json`)
```json
"voice": {
  "enabled": false,          // 기본 꺼짐. 콘솔에서 켠다
  "volume": 80,              // 0~100
  "interval_sec": 5.0,       // 재전송 주기 (펌웨어 반복이 안 먹으므로)
  "stop_delay_sec": 3.0,     // 이만큼 멈춰야 끈다
  "audio_id": "3512069",     // url 이 비었을 때만 사용
  "url": "/static/audio/lg/01_moving.mp3",
  "mode": 2,                 // 1=상위기 / 2=섀시
  "server_port": 8002
}
```

### ★ 서버 주소를 저장하지 않는 이유
`url` 은 **상대경로로 저장**하고 보낼 때 절대주소로 바꾼다.
`robot_voice.server_ip_for(robot_ip)` 가 로봇 쪽으로 UDP 소켓을 열어 **우리 로컬 주소를
되읽는다**(패킷은 안 보냄). 개발 PC든 현장 서버든 자동으로 맞는 IP가 나온다.
**설정에 IP를 적어두면 현장에서 반드시 어긋난다.**

## 8. 현장 이관 — 빌드 불필요

| | 이유 |
|---|---|
| **프론트 빌드 0** | UI가 배차 콘솔(서버 렌더링 HTML)에 있다. 파일 덮어쓰면 태블릿에도 반영 |
| **APK 재설치 0** | 콘솔 화면은 APK가 아니라 서버가 그린다 |
| **DB 마이그레이션 0** | 설정을 `system_settings.json` 에 저장 |
| **pip install 0** | `websocket-client` 는 백엔드가 이미 쓰는 패키지 |

→ **바뀐 파일 복사 + 서버 재시작이 전부.**

### ★ LTE 리스크 — ③번 방향
| | 방향 | 현장 |
|---|---|---|
| ①② | 서버 → 로봇 | 기존 배차에 쓰는 검증된 방향. 포트포워딩 되어 있음 |
| ③ | **로봇 → 서버** | **미검증.** CGNAT 에서 막힐 수 있음 |

**막히면 콘솔 드롭다운에서 `[내장]` 음성으로 바꾸면 된다** — 내장은 ③이 없어 네트워크와 무관.
문구가 "로봇이 임무수행중입니다"로 고정되는 것만 다르다.

### 폴백 하나 더 — 태블릿 재생
`TabletApp/app/src/main/assets/tablet.html:127` 에 이미 있다:
```javascript
function getAudioUrl() { return SERVER_URL + '/static/audio/please_move.mp3'; }
// 로봇이 막혔을 때(handleStuck) 재생
```
로봇 스피커가 막히면 이 경로를 쓸 수 있다. 다만 태블릿 스피커라 공장 소음에서
음량이 충분한지는 미검증.

## 9. 도구

```powershell
# 기종 조사 — 포트·caps·8090 탐색·9000 접속·재생
python scripts\audio_probe.py 192.168.30.110
python scripts\audio_probe.py 192.168.30.110 --play --mode 2 --audio-id 3512069
python scripts\audio_probe.py --diff        # S300 ↔ L150 caps·포트 비교

# 주행 감지 자동 재생 (백엔드 로직의 프로토타입, 운영에는 불필요)
python scripts\voice_on_move.py 192.168.30.110 --watch-only   # 소리 없이 관찰
python scripts\voice_on_move.py 192.168.30.110
```
**운영 중에는 스크립트를 켜지 말 것** — 백엔드와 동시에 재생 명령을 쏴서 소리가 겹친다.

## 10. L150 이식 체크리스트

1. **9000·9001 포트가 열려 있는가** → `python scripts\audio_probe.py 192.168.30.100`
2. **`mode:2`(섀시)로 소리가 나는가** → mode 1로 먼저 성공시키면 안 된다
3. **`playLanguage` 가 5(한국어)인가** → `GET :9001/custom_settings`
4. `--diff` 로 S300과 caps·포트 비교

기종별로 값이 달라질 수 있는 것은 설정(`system_settings.json`)으로 빠져 있어 코드 수정 불필요.

## 11. 미검증

1. **현장 LTE 에서 로봇→서버 방향(③)** — 사무실 WiFi 에서만 확인
2. **L150** — 오프라인이라 미확인
3. **배차 주행 시 `moveState` 값** — 원격제어에서는 `idle` 고정인 것만 확인
   (`speed` 로 판정하므로 동작에는 지장 없음)
4. 로봇이 mp3 를 매번 받는지 캐시하는지 — `uvicorn.access` 로그 레벨이 WARNING 이라 미측정
