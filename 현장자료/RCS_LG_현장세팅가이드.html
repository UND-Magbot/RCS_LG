01 — 세팅 순서

순서가 중요하다. 특히 DHCP 끄기는 맨 마지막이다

먼저 끄면 다른 장비를 붙일 때 주소를 못 받아 작업이 막힙니다. 각 단계의 확인을 통과해야 다음으로 넘어갑니다.

STEP 1

서버 노트북을 랜선으로 연결하고 WiFi 를 끈다

유선·무선을 동시에 켜두면 라우팅 우선순위가 흔들려 "됐다 안 됐다" 하는 증상이 납니다. IP 고정도 어댑터·SSID 프로필 단위라, 무선 프로필에 넣고 유선으로 통신하면 적용이 안 됩니다.

확인 WiFi 아이콘 꺼짐 · 이더넷만 연결됨

STEP 2

이더넷에 고정 IP 를 직접 입력한다

IP 주소192.168.39.110
서브넷24칸이 접두사 길이를 요구하면 255.255.255.0 이 아니라 24
게이트웨이192.168.39.1

라우터에서 DHCP 를 끄는 것과 장비에 IP 를 넣는 것은 다른 작업입니다. 끄기만 하면 주소를 아예 못 받아 169.254.x.x 가 뜹니다.

확인 Get-NetIPAddress -InterfaceAlias '이더넷' → PrefixOrigin = Manual · IP .110

Dhcp 로 나오면 고정이 그 어댑터에 안 걸린 것입니다. 08-21 에 나온 39.44 가 정확히 이 상태였습니다 — 아무도 입력한 적 없는 값이었습니다.

STEP 3

라우터 포트포워딩을 확인한다

태블릿 4대가 전부 이 규칙을 거쳐 서버에 들어옵니다. 어긋나면 태블릿 화면이 아예 안 뜹니다.

라우터포트대상용도
서버 TC700_5168495 8002 192.168.39.110 태블릿 → 관제 서버
로봇 TC700_5170086 8090 192.168.39.100 서버 → 로봇 제어

확인 두 규칙이 위 값 그대로인지 · TCP 로 등록됐는지

★ LG 기존 벤더의 8002 → 192.168.101.2 규칙이 남아 있을 수 있습니다. 남아 있으면 태블릿 요청이 우리 서버가 아니라 LG 장비로 배달됩니다. 포워딩 표를 열면 이것부터 지우세요.

STEP 4

그 다음에 라우터 DHCP 를 끈다

LG 표준 방식입니다. 겹칠 주소를 아예 없애는 것이라 STEP 2 를 마친 뒤에 합니다.

확인 ping 192.168.39.1 응답 · 노트북 IP 가 .110 유지

STEP 5

패치를 적용하고 백엔드를 올린다

작업 중인 로봇이 없는지 먼저 확인합니다. 랙을 들고 이동 중에 서버를 내리면 로봇이 그대로 멈춥니다.

  1. 백엔드 콘솔에서 Ctrl+C
  2. zip 의 BackEnd/ 를 C:\RCS_LG\BackEnd\ 에 경로 그대로 덮어쓰기
  3. cd C:\RCS_LG\BackEnd → .\run_local.ps1

확인 Invoke-RestMethod http://127.0.0.1:8002/ping → 응답

default_area.json 은 zip 에 일부러 넣지 않았습니다. 개발 PC 값이라 덮어쓰면 현장 맵이 엉뚱하게 바뀝니다. DB 스키마도 손댈 필요 없습니다 — job_points 테이블은 서버 시작 시 없으면 자동 생성됩니다.

STEP 6

로봇 연결 → 맵 작성 → 설정 3가지

맵을 새로 만들면 POI 번호가 전부 바뀝니다. 그래서 설정은 맵 작업 뒤에 합니다.

  1. 로봇이 관제에 온라인으로 뜨는지
  2. 맵 작성 · POI 등록 — C1(충전소) c1-1(사전접근) R1 R2(랙 보관) J1 J2(작업지점)
  3. 02 의 설정 3가지 를 반드시 수행

확인 콘솔에 타일 4개(R1·J1·R2·J2)가 짝지어 보이는지

APK 없이도 됩니다 — 태블릿 크롬에서 http://10.115.244.11:8002/api/dispatch/tablet/poi/{번호} 를 열고 ⋮ → 홈 화면에 추가 하면 전체화면 아이콘이 생깁니다.

앱을 처음 켜면 서버 주소와 위치(POI) ID 두 칸만 물어봅니다. R 번호를 넣으면 호출 화면, J 번호를 넣으면 확인 화면이 뜹니다. 나중에 바꾸려면 설정 초기화.

06 — 안 될 때 보는 순서

증상마다 봐야 할 곳이 다르다

증상 A

태블릿 화면이 안 뜬다

  1. 서버 PC IP 와 포워딩 대상이 같은지
  2. 라우터에 LG 기존 8002 규칙이 남아 있는지
  3. 태블릿 APN 이 plte-lgit 인지
  4. 앱 서버 주소가 10.115.244.11:8002 인지

태블릿 크롬에서 …:8002/ping 을 열어보면 5초에 갈립니다. 뜨면 네트워크는 정상이고 앱 설정 문제입니다.

증상 B

로봇이 안 움직인다

  1. 관제에 로봇이 온라인인지
  2. 백엔드 로그에 배송 모드 줄이 찍혔는지
  3. 안 찍혔으면 매핑 미등록
  4. 찍혔는데 안 가면 라우터 간 방향 불통(미해결)

태블릿 화면이 정상이어도 이건 별개 문제입니다.

증상 C

하차까지 되는데 복귀를 안 한다

  1. 로봇 관리에서 충전소가 지정됐는지
  2. 로그에 충전소 POI 없음 이 있는지

거의 항상 설정 1 누락입니다.

증상 D

호출 버튼이 비활성이다

  1. 짝 작업지점에 랙이 남아 있는지
  2. 치운 뒤 그 J 태블릿에서 [확인]

랙 감지 센서가 없어 사람이 눌러주는 것이 유일한 해제 수단입니다. 라이다로 판정하는 것은 실측 결과 불가능했습니다 — 로봇이 자기가 든 랙을 인식해 버립니다.

07 — 아직 안 된 것

현장에서 마주칠 수 있으니 미리 알아둘 것

#항목현장에서 어떻게 보이나

3 서버 재시작 복구 미검증 작업 중 서버가 꺼졌다 켜지면 어떻게 되는지 아직 확인 못 함. 정전 대비 필요
