### 🔧 수정한 동시성 결함 2건 (`dispatch_service.py`)

| | 증상 | 원인 | 조치 |
|---|---|---|---|
| **A** | 콘솔 [출발]이 동시에 2~3건 수락 → **태블릿 표시 경유지와 실제 이동 경로가 어긋남**(15회 중 3회 재현) | 상태 검사 → DB 저장 → `pending_route` 대입이 락 없이 갈라져 있음 | **로봇별 락**(`_route_locks`)으로 묶음. 먼저 온 요청이 락 안에서 `moving` 으로 바꾸므로 뒤는 거부 |

### 🤖 자동 사이클 스크립트 — `scripts/auto_cycle.py`

사람이 [확인]을 누르지 않고 전 사이클을 반복 실행. **백엔드·프론트 무수정**, 콘솔이 쓰는 API만 호출.
```
python scripts\auto_cycle.py --dry-run      # 흐름만 (로봇 안 움직임)
python scripts\auto_cycle.py --rounds 1     # 1사이클 — 반드시 옆에서 지켜볼 것
python scripts\auto_cycle.py --rounds 10    # 무인 반복
```
- 기본: J1 호출 → J2,J3,J4 경유 → 도착마다 **5초 후 자동 확인** → 복귀 → 10초 휴식
- 이상 감지 시 **①이동 취소(그 자리 정지, 잭 유지) → ②세션 정리 → ③스냅샷 저장 → ④정지**. `Ctrl+C` 도 동일
- 감시: 경로계산 실패 연속 4회 / 비상정지 / 원격모드 전환 / 바퀴 과부하 / 잭 거부(506) / 세션 failed / 단계 타임아웃
- ⚠️ **[확인]은 원래 사람이 안전을 승인하는 절차** → 이 스크립트는 **테스트 전용**. 현장 운영 금지
- ⚠️ **미검증**: 비상 정지가 실제로 로봇을 세우는지, 단계별 타임아웃 값(픽업/이동 300s, 복귀 420s는 추정치)
  → **1회차에서 일부러 `Ctrl+C` 를 눌러 로봇이 서는지 먼저 확인할 것.** 안 되면 무인 반복 금지
- 로그: `_logs/auto_cycle_*.jsonl`, 정지 시 `_logs/snapshot_*.json`

> 로봇 이동 이력(`/chassis/moves`)은 **`page_size` 파라미터가 무시되어 전체가 반환**된다(실측).
> 그래서 스크립트는 시작 시점의 최신 이동 id 를 기준선으로 잡고 그 이후만 판정한다.
> (이 처리가 없으면 과거 실패 기록을 현재 상황으로 오인해 즉시 오탐 정지함 — 실제로 겪음)

| **F** | 동기화했는데 `create_time` 이 옛날 날짜 | — | **정상입니다.** 덮어쓰기라 안 바뀜 → `last_modified_time` 으로 판정할 것 |

> 위는 "같은 코드 경로가 있다"는 사실이지, LG에서 같은 증상이 난다는 확인은 아닙니다.

**대응 방침**: 테스트 중 실제로 재현되면, VESA에 적용한 수정을 **LG 구조에 맞게 이식**합니다.
(코드 복사가 아니라 방식 이식 — VESA 쪽 커밋 `f2231fb` 참고)

## 3. 테스트 단계 (권장 순서)

### STEP 1. 로봇 연결 — 여기가 막히면 다 막힘
- [ ] 로봇 IP 확인, `:8090` 접속
- [ ] **LTE(M2M) / WiFi 중 어느 망으로 테스트할지 결정**
      LTE면 **유동 IP 문제**(하루에도 여러 번 변경)를 먼저 처리 — 고정 IP 또는 DDNS
- [ ] 온라인 판정이 `/chassis/current-map` 기준으로 도는지 (LTE에서 `/device/info` 무응답 대응)
- [ ] 대용량(맵핑)은 **WiFi 권장** — 작업일지 08-04 결론

### STEP 2. 맵 / POI
- [ ] 맵핑 (⚠️ 위 B·C 주의 — **충전기 분리 후 시작**)
- [ ] POI 등록: 충전소 `C1`, 경유지 **`C1-1`**(도킹 실패 예방), 랙 위치(standby), 작업 위치
- [ ] **랙 위치 POI 에 `rack_size` 지정** (`LG` / `LG2`) ← LG 고유. 이거 없으면 랙 정렬 실패
- [ ] 동기화 → **`last_modified_time`** 으로 반영 확인
- [ ] 동기화 후 로봇 위치가 유지되는지 (포즈 저장·복원 기능)
- [ ] ⚠️ **저장 후 `charging_id`·`standby_id`·POI 주소 재확인** (위 A)

### STEP 3. 랙 인식 (`align_with_rack`) — LG의 최대 난관
작업일지 08-06에 원리가 정리돼 있음. `Wrong rack size` 가 나오면:
- [ ] 로그의 **`detected(a,b)` 값을 그대로** `rack_specs.py` 에 반영 (도면 치수 아님)
- [ ] `leg_size` 가 실제 다리 지름과 맞는지 (LG2 = 25mm → 0.025). 크면 **캐스터를 다리로 오인**
- [ ] 랙 중앙 **체인/늘어진 물체 제거** (라이다에 가짜 depth 생성 — 소프트웨어로 못 거름)
- [ ] 검출이 흔들리면 관측 범위 **중앙값** 사용 (LG2 depth 0.52~0.57 → 0.545)
- [ ] 캐스터가 장애물로 잡히면 `margin` 확대 (0.05 → 0.08)

### STEP 4. 배차 콘솔 (핵심 운영 UI)
- [ ] 로봇 호출 — **리프팅(렉 포함)** / **리프팅(렉 없이)** / **서빙** 3종
- [ ] 가용 로봇 0대일 때 **예약** 등록 / 예약 취소
- [ ] **경유지 여러 개 등록 + [출발]**
- [ ] 우측 로봇 사이드바 — 온라인·배터리·상태 표시
- [ ] [직접 제어] 모달 — 방향 조종, 잭 업/다운, 충전소·대기장소 복귀, 시스템 재시작
- [ ] **[작업 강제 종료]** — 로봇은 그대로 두고 세션만 정리되는지

### STEP 5. 로봇 부착 태블릿
- [ ] 경유지 도착 시 [확인] 버튼 노출
- [ ] [확인] → 다음 경유지 진행
- [ ] **마지막 경유지 [확인] → 자동 종료(복귀)**
- [ ] [작업 종료] 버튼 동작
- [ ] 콘솔에서 [확인] 대행도 되는지

### STEP 6. 복귀 시퀀스
- [ ] 랙 반납 위치 정확도 (⚠️ 위 D — **앞에 내려놓는지 반드시 눈으로 확인**)
- [ ] `C1-1` 경유 후 충전소 도킹
- [ ] `chassis/moves` 에 **`creator: rcs` + `type: charge`** 가 생기는지로 판정

### STEP 7. 부팅 자동 복구 (LG 고유)
- [ ] 로봇 전원 껐다 켜기 → 온라인 전환 시 **current-map 자동 설정 + 충전소 기준 위치 재조정**
- [ ] 위치 재조정 시 **헤딩이 180° 뒤집히지 않는지** (08-07 수정 이력 있음)
- [ ] 작업 중인 로봇은 제외되는지

### STEP 8. 이상 상황 / 동시성
- [ ] 로봇 2대 이상 동시 운영
- [ ] 같은 POI 동시 호출
- [ ] 이동 중 통신 끊김 → 복구
- [ ] 세션 꼬임 시 [작업 강제 종료]로 회복되는지
