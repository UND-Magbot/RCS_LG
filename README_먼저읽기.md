## ★ ver 2 에서 고친 것 — 현장 보고 5건 중 4건

### 1. 충전소 복귀에 경유지를 안 쓰고 회피주행하던 것

**원인 — 함수 두 개가 활성 맵을 딱 하나만 봤습니다.**

```python
active_map = q.order_by(RobotMap.id.desc()).first()   # ← id 가 제일 큰 맵 1개
```

현장 맵은 둘로 쪼개져 있습니다.

```
map 27 :  C1   C1-1              W1 W2 W3 W5 W6 W7 W8 W9
map 30 :  C1         C1-2        W1 W2 W3 W4 W7          ← id 가 커서 항상 이 맵만 봤다
```

진입점 `C1-1` 은 **map 27 에만** 있는데 `_find_entry_poi` 는 map 30 만 뒤졌습니다.
못 찾으면 `_park_at_charger` 가 **경유지 이동을 통째로 건너뛰고** `charge` 한 방으로
충전소까지 자유주행합니다. 이것이 현장에서 보신 "회피주행" 입니다.

> `C1-1` 은 **로봇에 동기화하지 않는** 우리 DB 전용 POI 라(`scripts/entry_poi_move.py`),
> 맵을 다시 동기화해 map 30 이 새로 생겼을 때 따라오지 않았습니다.

**고친 것 — 활성 맵을 `id` 큰 것부터 전부 훑습니다.**
`<이름>-1` 은 이름이 유일해서 맵을 섞어도 엉키지 않습니다.

### 2. 예약지로 갈 때 경유지를 안 따라가던 것

**같은 뿌리입니다.** `waypoints()` 도 맵을 하나만 보고, 그 맵에 경유지가 없으면
**조용히 빈 목록**을 돌려줬습니다. 호출부는 그걸 "경유지 없음" 으로 보고
`standard`(로봇 자체 회피주행) 로 떨어집니다.

**고친 것 — 경유지가 나오는 첫 활성 맵을 씁니다.** 하나도 없으면 로그를 남깁니다.

> **여러 맵의 경유지를 섞지는 않습니다.** 같은 이름이 맵마다 전혀 다른 좌표로
> 존재하기 때문입니다(실측: map27 `W5` (0.80,-24.77) / map30 `W5` (-5.33,-9.86)).
> 한 맵을 통째로 고르는 것만 합니다.

### 3. 충전소 복귀 때 W3 까지 갔다가 되돌아오던 것

**원인 —** 충전소는 통로 **옆**에 있는데, 진입점 `C1-1` 에 제일 가까운 경유지가
통로를 지나친 **W3(2.06 m)** 입니다. 진입 후보가 2개뿐이라 **W3·W4 만** 잡히고
**W2 에는 아예 연결이 안 됐습니다.**

**고친 것 —** 충전소 전용 경유지(`C<n>-2`)가 있는 **그쪽 끝에만** 후보를 3개로 넓힙니다.

```
            [ 종전 ]                        [ ver 2 ]
W2 위    W2→W3→C1-2→C1-1    9.00 m   →   C1-2→C1-1           5.18 m
J2       W1→W2→W3→C1-2→C1-1 17.06 m  →   W1→W2→C1-2→C1-1    13.24 m
R1       W1→W2→W3→C1-2→C1-1 15.02 m  →   W1→W2→C1-2→C1-1    11.20 m
J1(EOL)  —                           →   W7→W4→C1-2→C1-1    51.60 m
```

**모든 경로에서 W3 가 빠집니다.**

> `ENTRY_CANDIDATES` 를 전역으로 올리면 안 됩니다. 코너를 가로질러 벽을 통과하는
> 경로가 나온 실측 기록이 있습니다. **충전소 쪽 끝에만** 적용했습니다.

### 4. 경유지가 다 걸러져도 `C1-2` 는 살립니다

로봇이 마지막 경유지 **바로 위**에 서 있으면 경유지 목록이 비는데, 종전에는
그대로 `standard` 로 나가면서 **충전소 진입선까지 같이 버렸습니다.**

### 5. 강제 종료 안내에서 **대차를 안 들고 있으면** 대차 문구를 뺌

종전에는 대차 유무와 상관없이 **항상** 이렇게 떴습니다.

```
⚠ [로봇] 작업을 전부 중지했습니다.
대차를 내리고 충전소로 이동합니다.
내려놓은 대차를 치워 주세요.      ← 없는 대차를 치우러 가게 만들었다
```

이제 대차를 **안 들고 있으면** 두 줄을 빼고 이렇게만 뜹니다.

```
⚠ [로봇] 작업을 전부 중지했습니다.
충전소로 이동합니다.
```

버튼 누른 직후 문구(`routers/dispatch.py`)와 목적지가 정해진 뒤 덮어쓰는
확정 문구(`dispatch_service._push_followup_notice`) **둘 다** 적용했습니다.

**전체 강제 종료에서 취소된 호출이 0건이면 그 줄도 뺍니다.** 종전에는
`"이 로봇이 잡고 있던 호출 0건도 취소되었습니다"` 가 그대로 떴습니다.

목적지는 예약 유무로 갈립니다 — **현재 JOB** 강제 종료는 대기 예약이 있으면
그 예약의 **R 지점**(표시 이름), 없으면 **충전소**. **전체** 강제 종료는 항상 충전소입니다.

> **모르면(로봇 통신 실패) 들고 있다고 봅니다.** 후속 동작이 잭다운을 판단하는
> 기준과 같습니다 — 안 들고 있는데 문구가 남는 건 해가 없지만, 들고 있는데
> 빠지면 대차가 통로에 방치됩니다.

## 적용 확인

| 확인할 것 | 정상이면 |
|---|---|
| 작업 종료 → 충전소 복귀 | **경유지를 따라감** (회피주행 아님) |
| 그때 지나는 경유지 | **W3 를 안 거침** · 마지막에 `C1-2` 를 거쳐 도킹 |
| 예약 이어받아 출발 | **경유지를 따라감** |
| 콘솔 좌·우 칸 이름 | **EOL → 자재실** / **자재실 → EOL** |
| [작업지점 이름] 저장 후 | 좌우 칸이 **그대로** |
| [직접 제어] → 수동 조작 | 아래 **전방 장애물** 줄이 **사라짐** |
| 대차 없이 강제 종료 | 안내에 **"대차를 내리고"** 가 **안 뜸** |
| 예약 없이 현재 JOB 종료 | **"충전소로 이동합니다"** |
| 예약 있을 때 현재 JOB 종료 | **"자재실 출발로 이동합니다"** 처럼 R 지점 이름 |
| 취소된 호출 0건 | **"호출 0건도 취소"** 줄이 **안 뜸** |
